## Уровни проверки

1. Детерминированные unit/contract tests: фильтры, score, состояния, handoff, конфиг, ревизии. Синтетические данные помечены как fixtures.
2. Интеграционные сценарии с управляемыми ошибками внешних адаптеров: retry, crash recovery, idempotency, бюджеты, права.
3. Малый LLM eval: 12 вручную размеченных кейсов — прямое подтверждение, опровержение, конфликт, разные даты, разные метрики, вторичный источник, недоступный документ, гипотеза, расчёт, prompt injection, пустая доказательная база, неоднозначная юрисдикция. Запустить по 3 раза на выбранной версии модели/промпта.
4. Реальный end-to-end прогон на 20 моделях с проверкой всех обязательных фильтров и выбранных сильных утверждений человеком перед демонстрацией. Ручной аудит фиксируется как таковой, не маскируется под полностью автоматическую точность.

Критерии LLM eval: нет выдуманных источников/цитат и утечки запрещённых полей; ни одного ложного pass, независимо от confidence, в размеченных критических unknown/fail кейсах. До запуска fixtures фиксируют role, input snapshot, checked_field, допустимое множество expected_values и critical=true/false. Для P02/P02V оцениваются результаты критериев, для P04 — Verification.status; у прочих ролей проверяются контрактные assertions, не смешиваемые с процентом статусов. Каждый заранее размеченный role+case+field при каждом из трёх повторов — одна единица знаменателя. Exact membership ответа в expected_values даёт успех; пропуск, ошибка схемы или отказ дают неуспех. Не менее 90% на noncritical единицах отдельно для каждой оцениваемой роли. Инфраструктурный сбой делает прогон eval незавершённым и не позволяет признать приёмку пройденной. Этот малый набор не даёт статистической гарантии качества; пороги не снижаются ради сдачи.

## Исторический порядок полной реализации до v1.3

1. Контракты, конфигурация, миграции, детерминированные фильтры и score (R02/R04/R06).
2. Источники, discovery, snapshots, дедупликация (R01).
3. Research, Critic, handoff, Verifier и prompt eval (R03/R04).
4. LangGraph runner/checkpointer, RunCommand/RunLease, retries, recovery, бюджеты, ручные ревизии (R07).
5. Карточки, сравнение, рейтинг, owner/public доступ (R05/R08).
6. Реальный прогон, аудит, деплой Aeza, backup и сдача (R08/R09).

Каждый этап имеет коммит с привязкой к требованиям и результат проверки. Перед первым этапом пользователь согласует baseline спек. Возникший пробел → сначала поправка спеки, затем код. Не обещать автоматическую публикацию или расходы на сервисы без имеющихся доступов и согласованного бюджета.

## Материалы сдачи

README: локальный запуск, переменные окружения, live/replay, доступ владельца, тесты, публикация, ограничения. DECISIONS: пять развилок из 12-decisions с фактическими итогами. LIMITATIONS: реальные ограничения и неисправности. Видео: 0:00–0:30 цель/обзор, 0:30–1:30 сравнение, 1:30–2:15 источники/агенты/отказы, 2:15–3:00 ограничения и развитие. До записи реального продукта видео считается только планом.

- A44: английские UI/карточки/ошибки/экспорты; исходные цитаты не переводятся молча.
- A45: два параллельных вызова у границы $25, timeout с неизвестным usage, retry, crash/resume и поздний settlement не обходят лимит и не удваивают расход; discovery включён.
- A46: известные usage fixtures каждого провайдера воспроизводят токены/кредиты/decimal стоимость по сохранённой PricingVersion; cached/reasoning подмножества не считаются дважды; free credits не скрывают потребление, unknown не равен нулю.
- A47: суммы owner UI, CSV/JSON и ledger совпадают на одинаковых фильтрах; роли и retries различимы, нулевой знаменатель даёт N/A, секретов нет; неавторизованное чтение owner usage запрещено.

## Приёмка оркестрации LangGraph v1.1

- A48: граф явно проводит pass через Critic/Verifier; fail/unknown не ранжируются; после разрешённого manual pass недостающие узлы выполняются. Два параллельных scope имеют разные thread IDs, метаданные и входы.
- A49: crash после domain result commit, но до checkpoint: resume повторно входит в узел, возвращает receipt и не делает второй внешний запрос. Crash после отправки до результата сохраняет unknown reserve и паузу; явный retry создаёт новый request_id и не освобождает старый резерв.
- A50: попытка старого worker после потери RunLease не записывает ни domain result, ни checkpoint и не запускает новый платный вызов; поздний usage уточняет только собственный расход.
- A51: несколько manual interrupts, повторный/устаревший ответ, restart worker и повторный Command: каждый вопрос разрешается один раз, версии проверяются, сохранённые платные шаги и ManualReview не дублируются. Бюджетная пауза не снимается чужим manual resume.
- A52: фактические payload Critic/Verifier и tool calls не содержат чужой chat history, score/confidence/impact или полного GraphState; приватный checkpoint/trace недоступен гостю. Нейтральность текста проверяется отдельно.
- A53: transport retry максимум 3 физические попытки; node retry не умножает их. Resume/time travel не откатывает usage, активное время и лимиты. Snapshot/receipt версии не смешиваются.
- A54: backup/restore включает схемы приложения и LangGraph в PostgreSQL и evidence; восстановленный граф продолжает работу с правильным checkpoint и расходами. Несовместимая graph/schema version блокирует resume до явного решения.
- A55: старая StageExecution-очередь не планирует этапы параллельно LangGraph; единственный источник переходов — граф. RunCommand управляет только запуском/паузой/продолжением.

## Приёмка изменений v1.2

- A56: интеграция на реальном PostgreSQL: параллельное резервирование не превышает run/study cap; уникальные квитанции; старый token не пишет checkpoint/pending writes/blobs. Конкурирующая смена владельца между проверкой и записью не обходит fencing; rollback/commit saver проверены, HTTP не выполняется под DB lock.
- A57: чистая установка и миграция сохранённого SQLite fixture сохраняют IDs, связи, суммы usage/reservations и evidence hashes; повтор миграции безопасен, конфликт checksum останавливает запуск. Production DB не удаляется автоматически.
- A58: HTML/PDF fixtures, redirect/private IP, DNS rebinding, oversized/decompression payload, timeout и robots запрет: политика соблюдается; неподдерживаемый документ не даёт pass. External Extract не получает ложных гарантий загрузки и не проходит обязательный фильтр самостоятельно.
- A59: CI запускает PostgreSQL tests и собирает Linux image; явный deploy доставляет тот же digest, сохраняет release manifest. Обычный push не вызывает deploy; secrets не попадают в artifacts/logs. Проверен rollback совместимого release и отдельный restore backup для несовместимого.
- A60: восстановление из внешней зашифрованной копии возвращает документы, usage и checkpoint; ключ восстановления доступен владельцу. Stale heartbeat/backup видны; отсутствие OOM/restart проверено при двух scopes на целевом VPS.
- A61: role settings зафиксированы, eval по прежним 12 кейсам × 3 повторения не снижает пороги; стоимость/latency показаны по ролям. Ошибки API делают eval неполным, не успешным. Фактическая доступность Astra и совместимость параметров проверяются отдельно от качества.
- A62: до полного batch выполнен один live assessment scope от поиска до карточки с evidence, Critic/Verifier и ledger. Искусственный сбой на fixture/контролируемом этапе доказывает resume без повтора сохранённого платного шага. Если live модель отсеяна, путь до карточки отказа подтверждён, но путь до рейтинга остаётся непоказанным; успешный fixture не подменяет live результат.

Исторический порядок v1.2: PostgreSQL/migrations + LangGraph recovery → evidence fetch/parser → один полный scope → owner/public → batch → deployment acceptance. Он заменён текущим планом v1.3 выше. Расширенный платный eval требует отдельного общего лимита, не выводимого умножением числа кейсов на $25. Первоначальный бюджет $25/run не является текущим общим бюджетом подборки из 20; действует cap $100 по 10-operations.

закрытый технический деплой из GitHub Actions по разделу 10. Приёмка этого шага:
синтетическая карточка через SSH-туннель, PostgreSQL readiness, ноль внешних API,
сохранение данных при restart, проверенный restore и зашифрованная копия на Mac.
Затем: Tavily/controlled fetch → постоянный worker → evidence/manual validation →
один live scope в пределах $25/run → batch 10–15 → полный owner/public интерфейс.
Для будущей полной версии публичный доступ требует домен/HTTPS и регулярные внешние backups; первоначальный read-only HTTP-прототип имел явное исключение v1.3, заменённое доменным дополнением v1.3.1. Успешный
технический выпуск не закрывает продуктовую приёмку A01–A62.
