# 11. Приёмка, eval и этапы реализации

Статус: DRAFT v0.3. Это план проверок; ни одна из них ещё не выполнялась на продукте.

## Проверяемые сценарии

| ID | Сценарий | Условие успешности |
|---|---|---|
| A01 | Новый live discovery | Из широкого discovery зафиксированы 10–15 уникальных базовых моделей (по умолчанию 12), по одному выбранному варианту каждой; реальные прочитанные URL и рынок вне СНГ; неполная выборка честно помечена и не считается выполнением R01 |
| A02 | Две компании одной модели | Один business model, два аналога, сохранена причина дедупликации; неоднозначность не скрыта |
| A03 | Каждый из F01–F10 по отдельности нарушен | fail и точный criterion ID/причина/доказательство; высокий score не компенсирует fail |
| A04 | Противоречие меняет порог | needs_review, обе версии видны, модель вне финального рейтинга |
| A05 | Нет доказательств / обе оценки выше порога | В первом случае unknown, во втором допустим pass с оговоркой; разные годы не объявлены автоматическим конфликтом |
| A06 | Запрещённые поля в handoff | Вызов Verifier не выполняется; ошибка validation и журнал; нет доступа к данным Critic через tools |
| A07 | Нормальный прогон двух агентов | Входы, версии и tool calls доступны в очищенном аудите; нет передачи ответа Verifier в Critic |
| A08 | Факт без source, выдуманный ID, цитата не из snapshot | Результат не публикуется как подтверждённый; ошибка либо unknown с причиной |
| A09 | Суждение/расчёт/неизвестная дата | Метод виден; расчёт воспроизводим по inputs; отсутствие даты не заменено текущей датой публикации |
| A10 | Ручной эталон балла и ничья | Формула/вклады/округление верны; сортировка возрастающая; ничья без искусственного преимущества |
| A11 | Unknown фактор / диапазон | Нет произвольного среднего и перенормировки; unavailable/provisional вне final ranking |
| A12 | Сравнение трёх карточек | Одинаковые поля/единицы; два объяснения различий и источник доступны в ручном двухминутном сценарии |
| A13 | Изменение весов/невалидный конфиг | Новая ревизия, старый результат неизменен; сумма ≠100 останавливает запуск до API |
| A14 | Таймаут, затем успех; постоянный сбой | Не более 3 попыток; растущая задержка; другие модели сохраняются; технический сбой не fail |
| A15 | Неверный ключ/баланс | Нет бесполезных повторов для всех моделей, run paused с понятной причиной |
| A16 | Убийство worker и resume | Сохранённые стадии не повторяются; lease восстанавливается; нет двойных карточек |
| A17 | Гость пытается запускать/править, CSRF, XSS | Мутации запрещены, текст экранирован, данные владельца не доступны |
| A18 | SSRF, redirect на private IP, prompt injection | Запрос к private IP не выполнен; инструкции страницы не меняют роль/схему/секреты |
| A19 | Деплой и backup restore | Сайт на Aeza доступен по TLS, перезапуск сохраняет данные, резервная копия восстанавливается |
| A20 | Комплект сдачи | История коммитов, README, решения 3–5, ограничения, реальный прогон, видео ≤3 минут |
| A21 | Ручное решение и повторная публикация | Evidence/reviewer/reason сохранены, зависимые оценки пересчитаны, старая публикация не мутирует |
| A22 | Лимит расходов/запросов | Новые платные вызовы прекращены до превышения локального бюджета резервирования, partial/paused явно показан |

## Уровни проверки

1. Детерминированные unit/contract tests: фильтры, score, состояния, handoff, конфиг, ревизии. Синтетические данные помечены как fixtures.
2. Интеграционные сценарии с управляемыми ошибками внешних адаптеров: retry, crash recovery, idempotency, бюджеты, права.
3. Малый LLM eval: 12 вручную размеченных кейсов — прямое подтверждение, опровержение, конфликт, разные даты, разные метрики, вторичный источник, недоступный документ, гипотеза, расчёт, prompt injection, пустая доказательная база, неоднозначная юрисдикция. Запустить по 3 раза на выбранной версии модели/промпта.
4. Реальный end-to-end прогон на 12 моделях с проверкой всех обязательных фильтров и выбранных сильных утверждений человеком перед демонстрацией. Ручной аудит фиксируется как таковой, не маскируется под полностью автоматическую точность.

Критерии LLM eval: нет выдуманных источников/цитат и утечки запрещённых полей; ни одного уверенного pass в размеченных критических unknown/fail кейсах; минимум 90% согласия по остальным размеченным статусам. Эти небольшие проверки не дают статистической гарантии качества. При провале — исправить промпт/валидацию и повторить затронутый eval, не снижать порог ради сдачи.

## Порядок реализации после согласования

1. Контракты, конфигурация, миграции, детерминированные фильтры и score (R02/R04/R06).
2. Источники, discovery, snapshots, дедупликация (R01).
3. Research, Critic, handoff, Verifier и prompt eval (R03/R04).
4. Очередь, retries, recovery, бюджеты, ручные ревизии (R07).
5. Карточки, сравнение, рейтинг, owner/public доступ (R05/R08).
6. Реальный прогон, аудит, деплой Aeza, backup и сдача (R08/R09).

Каждый этап имеет коммит с привязкой к требованиям и результат проверки. Перед первым этапом пользователь согласует baseline спек. Возникший пробел → сначала поправка спеки, затем код. Не обещать автоматическую публикацию или расходы на сервисы без имеющихся доступов и согласованного бюджета.

## Материалы сдачи

README: локальный запуск, переменные окружения, live/replay, доступ владельца, тесты, публикация, ограничения. DECISIONS: пять развилок из 12-decisions с фактическими итогами. LIMITATIONS: реальные ограничения и неисправности. Видео: 0:00–0:30 цель/обзор, 0:30–1:30 сравнение, 1:30–2:15 источники/агенты/отказы, 2:15–3:00 ограничения и развитие. До записи реального продукта видео считается только планом.

## Дополнительная приёмка v0.2

- A23: завершение первого batch США не открывает следующий рынок; состояние study и backlog сохраняется между run.
- A24: модель, найденная в нескольких источниках/циклах, не увеличивает число уникальных идей; новый рынок создаёт отдельную оценку применимости.
- A25: недоступный источник оставляет coverage gap; исчерпание бюджета — paused, а не «рынок изучен». Счётчики novelty воспроизводимы по сохранённым страницам и моделям.
- A26: закрытие study возможно только при выполнении выбранной после ревью политики; решение владельца и основания записаны. Рынки СНГ запрещены конфигурацией.
- A27: все новые страницы поддерживают owner/public доступ; переход от обзорного экрана к карточке и её доказательствам занимает не более двух действий. История расчёта и источники доступны без логина гостю только в опубликованной проекции.
- A28: дизайн соответствует согласованному направлению Kelpie без его бренда/контента; проверены адаптивность, контраст, клавиатура и reduced-motion.

Сначала демонстрационный run на 10–15 моделях США; затем дополнительные циклы покрытия по согласованному бюджету. Не утверждать, что один демонстрационный run доказал полноту рынка США или всего мира.

## Дополнительная приёмка v0.3

- A29: 40 компаний с дублирующими моделями дают отдельные корректные счётчики кандидатов, базовых моделей и вариантов; нет искусственного увеличения R01.
- A30: сервис записи для двух сегментов — одна база; существенные различия сохраняются вариантами с основаниями. Выводы/баллы не переносятся между вариантами без проверки.
- A31: round-robin по primary_group воспроизводим; пустые группы не заполняются выдумками; неоценённые модели остаются в backlog. Отбор выполнен до score и фильтров.
- A32: после отказа части выбранных моделей состав подборки не меняется; отказанные видны, рейтинг содержит только допущенные варианты.
- A33: модель с несколькими тегами показана один раз; неоднозначное объединение требует решения и сохраняет исходные документы. Публикация не меняется от правки текущего каталога.
- A34: два варианта одной базы не занимают два места в CEO-подборке; новый рынок не увеличивает метрику новых базовых идей. Кэш/ключи этапов различают assessment_scope_id.
- A35: достижение лимита до 30 кандидатов видно как недостигнутая цель discovery; при наличии 10–15 базовых моделей подборка допустима, при меньшем количестве не выдаётся за полную.
