# 04. Обязательные фильтры и проверка доказательств

Статус: APPROVED BASELINE v1.0 (пользователь, 15.11.2026). Фильтры не входят в взвешенную сумму: их нельзя компенсировать высоким баллом.

## Конфигурация критериев

Для каждого criterion_id: enabled (все ниже true), description, pass_rule, fail_rule, unknown_rule, required_evidence, jurisdiction_scope, threshold nullable. Эти определения хранятся в versioned config и передаются в промпт; приложение исполняет общий контракт pass/fail/unknown, а не дублирует текст правил в коде. Изменение enabled создаёт новый конфиг и помечает отклонение от исходного задания; штатный baseline не позволяет отключить обязательный критерий без ревью.

| ID | Pass | Fail | Unknown |
|---|---|---|---|
| F01 lawful | Есть относящееся к описанной деятельности и юрисдикции основание допустимости; перечислены необходимые условия | Есть применимый запрет | Только отсутствие найденных запретов или неясная юрисдикция |
| F02 online | Предложенная нами услуга, доставка результата и обслуживание полностью онлайн | Нужны собственные физические операции для предоставления услуги | Неясно, кто осуществляет физическую часть |
| F03 own_license | Для описанной роли до первого клиента не требуется собственная специальная лицензия; учтены партнёры | Такая лицензия требуется | Нет достаточной проверки применимости |
| F04 recurring | Документированная подписка или комиссия с регулярных операций и применимый механизм для предлагаемой модели | Только разовая продажа/проект без механизма повторяемости | Маркетинговое обещание без ясной схемы выручки |
| F05 no_credit_risk | Описанный поток денег/обязанностей не делает нас кредитором/гарантом | Принимаем кредитный риск | Роль/договорные обязанности неясны |
| F06 no_insurance_risk | Не принимаем страховой риск | Принимаем такой риск | Роль неясна |
| F07 no_custody | Чужие средства не хранятся у нас; расчёты непосредственно через внешнего оператора | Храним клиентские средства | Неясен поток средств |
| F08 no_trading | Продукт не является трейдингом | Основная деятельность — трейдинг | Пограничная модель |
| F09 no_state_service | Не выполняем государственную функцию и в baseline не строим основной сбыт на госзаказе | Государственная функция/госуслуга либо госзаказ как основа | Неясен заказчик/функция |
| F10 scale | Хотя бы один сопоставимый аналог имеет документированную стоимость от $300 млн | Конкретный аналог может быть опровергнут, но это не доказывает fail всей модели | Не найден подтверждённый крупный аналог, найден только малый, есть только выручка/сумма раунда либо существенный конфликт |

F09: консервативная трактовка, включая основной сбыт на госзаказе, принята пользователем как допущение проекта, не как уточнение CEO. F10: отсутствие подтверждённого крупного аналога всегда unknown; лимит поиска не доказывает отсутствие аналога в мире. Конвертация валют требует курса с датой и паспорта расчёта.

## Процедура

1. Исследователь собирает базовые документы и предложения CriterionResult.
2. Валидатор проверяет структуру и наличие доказательств для pass И fail. Служебная проверка применимости сопоставляет цитату, scope и pass_rule/fail_rule; отсутствие ID/цитаты проверяется детерминированно, смысловая применимость — отдельным ограниченным LLM-вызовом с evidence-пакетом, без решения исследователя. Неподтверждённый pass/fail становится unknown с причиной. Сбой этой проверки оставляет evaluation_state=technical_failed/result=null, а не unknown.
3. Общий агрегатор применяет таблицу статусов из 03-data. Все отказы попадают в журнал: model_id, criterion_id, evidence IDs, причина, дата, config_hash.
4. Только pass передаётся критику. Если в дальнейшей проверке обнаружено существенное противоречие фильтра, пересчитать затронутый критерий и eligibility. Нельзя оставить модель в рейтинге по старому pass.

Автоматическая проверка законности ограничена анализом документов и не является юридическим заключением. Отсутствие подходящих документов оставляет unknown, даже если это делает рейтинг пустым. Не требовать доказательства общего отсутствия всех возможных регуляторных рисков: проверка ограничена явно описанной деятельностью и юрисдикцией, с видимыми границами.

## Конфликты

Проверить сущность/метрику/период/географию → найти происхождение → прочитать доказательства → до двух уточняющих запросов на существенный конфликт в пределах общего бюджета → сопоставить версии. Сохранять обе версии, даже если конфликт разрешён. Новизна и первичность — факторы, не автоматическая истина.

Если конфликт меняет обязательный фильтр — needs_review, без финального рейтинга. Если обе допустимые альтернативы проходят порог, фильтр можно оставить pass с объяснением. Для шкалы рейтинга полностью обоснованные альтернативы дают диапазон и консервативный final по 07-ranking; незавершённая проверка остаётся provisional вне рейтинга. Не усреднять несопоставимые величины, не выбирать значение голосованием агентов.

## Ручное разрешение

Владелец видит вопрос, альтернативы и документы; вводит решение, обоснование и минимум один EvidenceLink.id либо оставляет unresolved. Ручное утверждение без доказательства не превращает обязательный фильтр в pass. Исправление создаёт AnalysisRevision по 03-data, сохраняет историю и инвалидирует зависимые результаты.

Если ранее Critic/Verifier не запускались из-за needs_review/fail и после правки eligibility=pass, оркестратор ставит Critic → Verifier → reconciliation → factors → card в очередь. До завершения всех стадий analysis_status=pending/running и итогового рейтинга нет. Если правка меняет вход уже выполненного Critic, в текущем run нельзя публиковать старую проверку как актуальную: требуется новый run/recheck с новым исходным пакетом. Ответ Verifier не передаётся критику. Если вход критика не затронут, переиспользование разрешается только по совпадающему input hash и manifest.

D-09 согласовано: отсутствие подтверждённого крупного аналога всегда unknown, независимо от найденных малых аналогов.
