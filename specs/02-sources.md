# 02. Источники, поиск и воспроизводимость

Статус: APPROVED BASELINE v1.3 (пользователь, 15.11.2026).

## Целевой пакет источников v1.4

Для отдельного Helpdesk follow-up разрешены до 12 Tavily-запросов и до 16 новых чтений, включая явно заданные приоритетные первичные URL. Они проходят тот же controlled fetch, parser, policy и immutable snapshot; ссылки и сниппеты сами по себе не доказательства. Приоритетные документы читаются до дополнительных поисковых результатов, чтобы продуктовая выдача не исчерпала квоту правовых источников. Исходные defaults 4 запроса/6 чтений и frozen-пакеты двадцати моделей не меняются. Пакет замораживается до агентных стадий; дополнительные документы требуют новой ревизии.

Пакет должен покрыть правила Texas/Austin для описанного SaaS/home-office, налоги/регистрацию, защиту данных, условия внешнего платёжного оператора, повторяющуюся монетизацию и подтверждённого крупного аналога. Приоритеты: Texas Business Permits Office, применимые Texas statutes, Comptroller, федеральные SBA/FTC, официальные продуктовые/ценовые страницы и сообщение о завершённой оценённой сделке аналога. Дата исторической оценки обязательна. Пробелы, запреты чтения и противоречия сохраняются; лимиты парсера не обходятся ради pass.

## Объём прототипа v1.3

Реальный поиск через существующий Tavily и controlled fetch должен дать 20 разных базовых моделей США до обязательной фильтрации. Начальные направления запросов ниже сохраняются; TechCrunch используется для обнаружения, документы компаний и первоисточники — для проверки. Дедупликация и прочитанный источник обязательны. Ориентир 30–50 кандидатов, глобальный backlog, матрица покрытия и правила насыщения ниже относятся к этапу после прототипа: их реализация не нужна для первой подборки. Достаточно фиксированного списка 20 моделей с основаниями включения и одним сценарием; меньше 20 — явно неполная подборка. После фиксации отказы не заменяются. Поиск, чтение и анализ оплачиваются из общего бюджета подборки. Новая сверка тарифов не требуется.

## Контракт получения кандидатов

Основной способ — web search через адаптер Tavily Search (выбран пользователем 15.11.2026), затем чтение открытых страниц. Поиск — способ обнаружения, доказательством служит документ источника. Сгенерированный поиском ответ и сниппет не являются достаточным доказательством обязательного фильтра. Tavily Search с VPS вернул HTTP 200, ключ и права файла проверены. Tavily Extract предложен для извлечения страниц; Firecrawl, Linkup, Exa и You.com рассматриваются как альтернативы, их подключение и платные тарифы не утверждены.

Начальные направления запросов в конфиге: subscription software, recurring transaction marketplace, online business service, developer tools, consumer subscription, workflow automation. Для каждого: компания, клиент, задача, способ регулярной оплаты и рынок. Не отбирать только по известной оценке $300 млн на discovery: масштаб проверяется позже, чтобы были видны причины отсева.

Шаги:
1. Выполнить по одному стартовому запросу на каждое направление; записать запрос, время, результаты и порядок выдачи.
2. Накапливать кандидатов с реальными URL, пока можно сформировать 20 разных моделей в рамках общего бюджета. Широкий пул candidate_goal=40/candidate_cap=50 остаётся настройкой будущего каталога, а не обязательным этапом прототипа. Сохранить фактически полученные результаты и причины исключения дублей.
3. Прочитать страницу продукта/цен/описания для каждого кандидата в пределах бюджета. Нечитаемые страницы — discovery issue, не доказательство отсутствия бизнеса.
4. Нормализовать компании в базовые модели и варианты по правилам 13-catalog. Бренды не создают новые модели; существенное различие сегмента создаёт отдельный вариант оценки. Назначить основную группу по задаче и дополнительные теги с обоснованием.
5. Сформировать подборку из 20 уникальных базовых моделей, один вариант каждой базы, с разнообразием по существующим направлениям поиска. Сохранить состав, источники и основания дедупликации; рейтинг и обязательные фильтры не участвуют в выборе победителей заранее.
6. Зафиксировать batch. После начала фильтров не заменять отклонённых кандидатами из резерва. Новый набор — новый run.

Если неоднозначно, дубликат ли модель, сохранить обе с меткой и приостановить финализацию выборки до проверки владельцем. Нельзя тихо выбирать наиболее перспективные модели до фильтрации.

## Контракт чтения

FetchResult: requested_url, final_url, fetched_at UTC, status, title, publisher, published_at nullable, body_text, content_hash, extraction_method, error nullable. Сохранить извлечённый текст внутренне; публично — короткие релевантные фрагменты, ссылки и даты, а не зеркала статей. Даты не выдумывать; неизвестная дата публикации отображается как неизвестная.

Таймаут чтения 20 секунд, максимум 5 редиректов и 5 МБ документа. HTML и текстовые PDF поддерживаются; OCR/логины/paywall не входят в v1. Невозможность прочитать документ не заменяется «знаниями модели». Не обходить ограничения доступа. Ограничения robots/сайта учитываются адаптером; запрещённые страницы остаются inaccessible.

Защита чтения: только HTTP(S), запрет localhost/private/link-local/metadata адресов, проверка DNS и каждого редиректа, запрет URL с credentials. Извлечённый HTML не исполняется. Внешний текст — недоверенные данные, не инструкции агенту.

## Свежесть и повтор

В новом run документы читаются заново; внутри run одинаковый URL можно брать из неизменяемого snapshot. Discovery re-run на сохранённой выборке создаёт новый run, сохраняя candidate IDs и обновляя доказательства. Offline replay использует только snapshots и помечается как replay, не как свежий web-анализ. Изменившийся web и недетерминированный LLM не обещают идентичный повтор; детерминированно воспроизводится расчёт на сохранённых результатах.

Дата события и дата публикации различаются. Историческая оценка допускается как свидетельство достигнутого масштаба с датой; найденная более поздняя существенная переоценка должна учитываться, а не игнорироваться. Для меняющихся тарифов/условий нужен документ, прочитанный в текущем run; это не гарантирует истинность страницы.

Product Hunt/G2/Capterra не являются доказательством масштаба $300 млн или гарантией спроса.

### Предлагаемая граница глубокого исследования

Вводится MarketStudy — исследование определённого рынка в явно заданной области. Для первого цикла: США, шесть направлений из начала документа, три семейства discovery-источников из таблицы. Это 18 ячеек покрытия, а не все существующие отрасли США. Два разных поисковых запроса на ячейку, до 10 результатов на запрос. Для публикаций стартовое окно — последние 24 месяца с явно записанными датами; для каталогов — текущая выдача. Ограничения поиска и языков отражаются в отчёте покрытия.

Discovery выполняется циклами в пределах согласованного бюджета; стандартный один run на 20 моделей не обязан закрыть всю матрицу. Кандидаты сохраняются в backlog с дедупликацией между run. Статус ячейки: pending/in_progress/covered/blocked. Для каждого запланированного запроса фиксируются текст, scope/version, время, состояние выполнения (succeeded/failed), количество результатов и явный empty_result при успешной пустой выдаче. Для каждого полученного результата в объявленном лимите фиксируется disposition: read с source/snapshot ID; duplicate со ссылкой на уже прочитанный snapshot и причиной совпадения; excluded с проверяемой причиной несоответствия scope; inaccessible с причиной невозможности чтения; pending, если обработка не завершена. Новый URL или сниппет без прочитанного документа не считается read.

covered разрешён только когда выполнены все запланированные запросы, каждый их результат получил конечный disposition, нет pending/inaccessible и хотя бы один релевантный документ реально прочитан (либо доступен как подтверждённый duplicate прочитанного snapshot). Все-пустые выдачи, только исключённые результаты или отсутствие пригодного документа дают blocked с причиной, а не covered и не «на рынке нет моделей». Ошибка запроса или inaccessible оставляют видимый пробел: статус in_progress, пока ещё идёт обработка/повтор, затем blocked при невозможности завершить в текущем плане. Повторная выдача одного документа может завершить обработку результатов, но не увеличивает число уникальных прочитанных страниц. covered означает выполнение этого протокола в фиксированном scope, не исчерпывающий поиск и не процент всех бизнесов страны. Отдельный реестр сохраняет запросы, результаты, dispositions, источники и причины решений.

Предлагаемый критерий перехода к следующему рынку: все обязательные ячейки covered; backlog в рамках заданного поиска обработан либо явно отложен владельцем с причиной; два последовательных дополнительных цикла, каждый минимум на 20 новых уникальных прочитанных страницах, дали менее 10% новых уникальных бизнес-моделей относительно числа этих страниц. Результат формулируется «цикл исследования завершён; наблюдается насыщение в заданной области», не «рынок полностью изучен». Порог и политика завершения приняты пользователем как рабочие настройки baseline, не научно доказанная метрика полноты. Если бюджет/время закончились, остались blocked-ячейки или не удалось получить минимум 20 новых страниц для требуемого цикла, study остаётся paused с признаком incomplete и конкретной причиной; следующий рынок не запускается автоматически. Недостаток новых страниц не заменяется нулём новых моделей и сам по себе не засчитывается как насыщение.

Новизна вычисляется по всем новым базовым моделям, извлечённым из прочитанных страниц допустимого цикла, включая кандидатов сверх рабочего candidate_cap и записи, отложенные из текущей подборки. Достижение cap не обнуляет числитель. Если из-за бюджета или другой ошибки извлечение/нормализация прочитанных страниц не завершены, novelty_ratio=null и цикл не может подтверждать насыщение. В знаменатель входят только новые уникальные прочитанные страницы; дубликаты и inaccessible не добавляются. Источник каждой учтённой модели и состав знаменателя сохраняются для воспроизводимости.

Окончательное закрытие study и выбор следующего рынка делает владелец только после выполнения согласованной политики завершения, видя покрытие и пробелы. Чтобы заменить недоступное семейство, изменить запросный план или сузить область, владелец создаёт новую scope_version с причиной, перечнем изменений и явными исключениями; старые запросы, ячейки и результаты остаются неизменными и доступны в истории. Для новой версии повторно оцениваются затронутые ячейки и условия завершения; прежний blocked не превращается автоматически в covered. Публичный отчёт показывает текущую область, исключённые направления/источники и причины, а не скрывает пробелы за новой версией. Изменение scope само по себе не закрывает study и не открывает следующий рынок. Возможные следующие рынки: Великобритания, Канада, Австралия, отдельные страны Европы и Азии; порядок пока не согласован. СНГ исключается из рынков исследования и запуска, как в исходном задании. Список исключённых стран версионируется в конфиге, не угадывается агентом по языку сайта.

Бизнес-модель имеет глобальный ID; проверка применимости и score привязаны к паре model+market+scenario. Один и тот же тип модели не считается новой идеей только из-за другой страны. Результаты разных юрисдикций не смешиваются в одном итоговом рейтинге без отдельной согласованной методики.

Политика разнообразия — отбор разных базовых моделей до фильтрации, а не дополнительный рейтинговый фактор. Новизна исследования рынка считается по base_model_id: новый бренд, вариант или страна не увеличивают число новых базовых идей. Счётчики компаний, базовых моделей и вариантов показываются раздельно.

## Получение доказательств v1.2

Tavily Search остаётся поиском URL. Основной путь доказательства — контролируемая HTTP-загрузка исходного документа: HTTPX streaming с лимитом 5 МБ также на декодированный контент, общим deadline 20 s, до 5 редиректов и проверкой каждого назначения. DNS-проверка должна соответствовать фактическому peer IP соединения, чтобы исключить DNS rebinding; отдельный предварительный resolve не достаточен. robots/правила сайта проверяются до загрузки, отказы сохраняются. Контракт проверяется на тестовом HTTP/DNS стенде без обращения к реальным private endpoints.

HTML извлекается Trafilatura, текстовый PDF — pypdf; версии фиксируются после проверки fixtures с таблицами, pricing, статьёй и PDF-отчётностью. Сохранять исходный документ приватно, извлечённый текст, hash каждого артефакта, parser/version, fetched_at, requested/final URL, MIME и доступные даты. PDF-парсинг выполняется с отдельным ограничением CPU/времени/памяти; scanned PDF без текста — unsupported, не пустой успешный документ. JS-rendering, OCR и обход paywall не входят в v1.

Tavily Extract — опциональный внешний путь, выключенный по умолчанию до отдельной интеграционной проверки. Его текст имеет provenance=external_extract, provider/version/request_id и unknown для неполученных redirect/robots metadata. Внутреннюю загрузку провайдера нельзя выдавать за проверенную нашим fetcher. Пока соответствие обязательной политике загрузки не подтверждено, Extract-текст используется для discovery/поиска первичного источника, но не для самостоятельного pass обязательного критерия. Недоступность основного документа приводит к evidence gap/unknown согласно 04, а не к выдуманному подтверждению. Расход Extract входит в общий лимит.

FetchResult дополняется acquisition_method, policy_status, redirect_chain nullable, raw_artifact_ref nullable, raw_hash nullable, parser_version и extraction_warnings[]. Источник даты и признаки неполного текста сохраняются. Сниппеты и ответы поискового LLM не становятся документами доказательства. Один и тот же fixture должен давать воспроизводимую цитату/смещение и сохранённый hash при фиксированном parser.

Основания выбора: [Trafilatura: HTML text/metadata extraction](https://trafilatura.readthedocs.io/en/latest/), [pypdf: text extraction и ограничения памяти/OCR](https://pypdf.readthedocs.io/en/stable/user/extract-text.html). Используем только extraction API над уже загруженными байтами; встроенные загрузчики библиотек не обходят контролируемый HTTP-путь. Начальные parser limits: 20 s, 512 MiB и 100 страниц PDF на документ; превышение — extraction_limit, не доказательство отсутствия факта. Эти значения входят в config и проверяются на fixtures.
