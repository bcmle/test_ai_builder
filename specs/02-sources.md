# 02. Источники, поиск и воспроизводимость

Статус: DRAFT v0.4.

## Контракт получения кандидатов

Основной способ — web search через адаптер поискового API (предварительный кандидат: Tavily), затем чтение открытых страниц. Поиск — способ обнаружения, доказательством служит документ источника. Сгенерированный поиском ответ и сниппет не являются достаточным доказательством обязательного фильтра.

Начальные направления запросов в конфиге: subscription software, recurring transaction marketplace, online business service, developer tools, consumer subscription, workflow automation. Для каждого: компания, клиент, задача, способ регулярной оплаты и рынок. Не отбирать только по известной оценке $300 млн на discovery: масштаб проверяется позже, чтобы были видны причины отсева.

Шаги:
1. Выполнить по одному стартовому запросу на каждое направление; записать запрос, время, результаты и порядок выдачи.
2. Накапливать кандидатов с реальными URL для одной подготовки подборки: candidate_goal=40, candidate_cap=50 (ориентир 30–50). Это цель и верхняя граница рабочего пула одной подборки, не лимит записей или идей всего MarketStudy. Для подготовки разрешены несколько discovery-циклов; в одном цикле до 6 дополнительных запросов, если не хватает материала. Уже обнаруженные сверх cap кандидаты не теряются: сохраняются в backlog для последующих подборок. Все циклы расходуют общий бюджет MarketStudy; заполненный пул сам по себе не разрешает дополнительные расходы.
3. Прочитать страницу продукта/цен/описания для каждого кандидата в пределах бюджета. Нечитаемые страницы — discovery issue, не доказательство отсутствия бизнеса.
4. Нормализовать компании в базовые модели и варианты по правилам 13-catalog. Бренды не создают новые модели; существенное различие сегмента создаёт отдельный вариант оценки. Назначить основную группу по задаче и дополнительные теги с обоснованием.
5. Сформировать подборку по кругу из основных групп задач по алгоритму 13-catalog: 10–15 уникальных базовых моделей, по умолчанию 12, один вариант каждой базы. Сохранять состав, основания выбора, объединения и оставшийся backlog.
6. Зафиксировать batch. После начала фильтров не заменять отклонённых кандидатами из резерва. Новый набор — новый run.

Если неоднозначно, дубликат ли модель, сохранить обе с меткой и приостановить финализацию выборки до проверки владельцем. Нельзя тихо выбирать наиболее перспективные модели до фильтрации.

## Где брать доказательства

| Вопрос | Предпочтительные документы | Ограничение |
|---|---|---|
| Продукт и повторяемая выручка | Официальный продукт, pricing, условия подписки | Маркетинг не доказывает спрос |
| Масштаб компании | Сообщение компании/инвестора о стоимости, биржевая отчётность/данные, публикация с указанным происхождением оценки | Сумма раунда не равна valuation |
| Ограничения деятельности | Официальные регуляторы и документы по релевантной деятельности/юрисдикции | Отсутствие найденного запрета не доказывает законность |
| Клиенты и барьеры | Документы покупателей, публичные условия закупки, кейсы с раскрытым происхождением | Отзывы и кейсы могут быть выборочными |
| Риски | Документация конкурентов, условия, независимые публикации, финансовые сведения | Прогноз отделять от факта |

Дополнительный discovery-каталог: [YC Companies](https://www.ycombinator.com/companies). При проверке 15.11.2026 страница не отдала извлекаемый текст через использованный инструмент; не делать её обязательной зависимостью и не заявлять готовый парсер. Поиск открытого web достаточен для исходного задания.

[Документация Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search) подтверждает возможность поисковых запросов и возврата URL/контента. Конкретные лимиты и стоимость выбранного тарифа проверяются перед интеграцией. Наличие доступного аккаунта не предполагается.

## Контракт чтения

FetchResult: requested_url, final_url, fetched_at UTC, status, title, publisher, published_at nullable, body_text, content_hash, extraction_method, error nullable. Сохранить извлечённый текст внутренне; публично — короткие релевантные фрагменты, ссылки и даты, а не зеркала статей. Даты не выдумывать; неизвестная дата публикации отображается как неизвестная.

Таймаут чтения 20 секунд, максимум 5 редиректов и 5 МБ документа. HTML и текстовые PDF поддерживаются; OCR/логины/paywall не входят в v1. Невозможность прочитать документ не заменяется «знаниями модели». Не обходить ограничения доступа. Ограничения robots/сайта учитываются адаптером; запрещённые страницы остаются inaccessible.

Защита чтения: только HTTP(S), запрет localhost/private/link-local/metadata адресов, проверка DNS и каждого редиректа, запрет URL с credentials. Извлечённый HTML не исполняется. Внешний текст — недоверенные данные, не инструкции агенту.

## Свежесть и повтор

В новом run документы читаются заново; внутри run одинаковый URL можно брать из неизменяемого snapshot. Discovery re-run на сохранённой выборке создаёт новый run, сохраняя candidate IDs и обновляя доказательства. Offline replay использует только snapshots и помечается как replay, не как свежий web-анализ. Изменившийся web и недетерминированный LLM не обещают идентичный повтор; детерминированно воспроизводится расчёт на сохранённых результатах.

Дата события и дата публикации различаются. Историческая оценка допускается как свидетельство достигнутого масштаба с датой; найденная более поздняя существенная переоценка должна учитываться, а не игнорироваться. Для меняющихся тарифов/условий нужен документ, прочитанный в текущем run; это не гарантирует истинность страницы.

### Предлагаемая граница глубокого исследования

Вводится MarketStudy — исследование определённого рынка в явно заданной области. Для первого цикла: США, шесть направлений из начала документа, три семейства discovery-источников из таблицы. Это 18 ячеек покрытия, а не все существующие отрасли США. Два разных поисковых запроса на ячейку, до 10 результатов на запрос. Для публикаций стартовое окно — последние 24 месяца с явно записанными датами; для каталогов — текущая выдача. Ограничения поиска и языков отражаются в отчёте покрытия.

Discovery выполняется циклами в пределах согласованного бюджета; стандартный один run на 12 моделей не обязан закрыть всю матрицу. Кандидаты сохраняются в backlog с дедупликацией между run. Статус ячейки: pending/in_progress/covered/blocked. Для каждого запланированного запроса фиксируются текст, scope/version, время, состояние выполнения (succeeded/failed), количество результатов и явный empty_result при успешной пустой выдаче. Для каждого полученного результата в объявленном лимите фиксируется disposition: read с source/snapshot ID; duplicate со ссылкой на уже прочитанный snapshot и причиной совпадения; excluded с проверяемой причиной несоответствия scope; inaccessible с причиной невозможности чтения; pending, если обработка не завершена. Новый URL или сниппет без прочитанного документа не считается read.

covered разрешён только когда выполнены все запланированные запросы, каждый их результат получил конечный disposition, нет pending/inaccessible и хотя бы один релевантный документ реально прочитан (либо доступен как подтверждённый duplicate прочитанного snapshot). Все-пустые выдачи, только исключённые результаты или отсутствие пригодного документа дают blocked с причиной, а не covered и не «на рынке нет моделей». Ошибка запроса или inaccessible оставляют видимый пробел: статус in_progress, пока ещё идёт обработка/повтор, затем blocked при невозможности завершить в текущем плане. Повторная выдача одного документа может завершить обработку результатов, но не увеличивает число уникальных прочитанных страниц. covered означает выполнение этого протокола в фиксированном scope, не исчерпывающий поиск и не процент всех бизнесов страны. Отдельный реестр сохраняет запросы, результаты, dispositions, источники и причины решений.

Предлагаемый критерий перехода к следующему рынку: все обязательные ячейки covered; backlog в рамках заданного поиска обработан либо явно отложен владельцем с причиной; два последовательных дополнительных цикла, каждый минимум на 20 новых уникальных прочитанных страницах, дали менее 10% новых уникальных бизнес-моделей относительно числа этих страниц. Результат формулируется «цикл исследования завершён; наблюдается насыщение в заданной области», не «рынок полностью изучен». Порог и политика завершения остаются проектным предложением на согласование, не научно доказанной метрикой полноты. Если бюджет/время закончились, остались blocked-ячейки или не удалось получить минимум 20 новых страниц для требуемого цикла, study остаётся paused с признаком incomplete и конкретной причиной; следующий рынок не запускается автоматически. Недостаток новых страниц не заменяется нулём новых моделей и сам по себе не засчитывается как насыщение.

Новизна вычисляется по всем новым базовым моделям, извлечённым из прочитанных страниц допустимого цикла, включая кандидатов сверх рабочего candidate_cap и записи, отложенные из текущей подборки. Достижение cap не обнуляет числитель. Если из-за бюджета или другой ошибки извлечение/нормализация прочитанных страниц не завершены, novelty_ratio=null и цикл не может подтверждать насыщение. В знаменатель входят только новые уникальные прочитанные страницы; дубликаты и inaccessible не добавляются. Источник каждой учтённой модели и состав знаменателя сохраняются для воспроизводимости.

Окончательное закрытие study и выбор следующего рынка делает владелец только после выполнения согласованной политики завершения, видя покрытие и пробелы. Чтобы заменить недоступное семейство, изменить запросный план или сузить область, владелец создаёт новую scope_version с причиной, перечнем изменений и явными исключениями; старые запросы, ячейки и результаты остаются неизменными и доступны в истории. Для новой версии повторно оцениваются затронутые ячейки и условия завершения; прежний blocked не превращается автоматически в covered. Публичный отчёт показывает текущую область, исключённые направления/источники и причины, а не скрывает пробелы за новой версией. Изменение scope само по себе не закрывает study и не открывает следующий рынок. Возможные следующие рынки: Великобритания, Канада, Австралия, отдельные страны Европы и Азии; порядок пока не согласован. СНГ исключается из рынков исследования и запуска, как в исходном задании. Список исключённых стран версионируется в конфиге, не угадывается агентом по языку сайта.

Бизнес-модель имеет глобальный ID; проверка применимости и score привязаны к паре model+market+scenario. Один и тот же тип модели не считается новой идеей только из-за другой страны. Результаты разных юрисдикций не смешиваются в одном итоговом рейтинге без отдельной согласованной методики.

Политика разнообразия — отбор разных базовых моделей до фильтрации, а не дополнительный рейтинговый фактор. Новизна исследования рынка считается по base_model_id: новый бренд, вариант или страна не увеличивают число новых базовых идей. Счётчики компаний, базовых моделей и вариантов показываются раздельно.
