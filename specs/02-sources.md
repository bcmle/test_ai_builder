# 02. Источники, поиск и воспроизводимость

Статус: DRAFT v0.1.

## Контракт получения кандидатов

Основной способ — web search через адаптер поискового API (предварительный кандидат: Tavily), затем чтение открытых страниц. Поиск — способ обнаружения, доказательством служит документ источника. Сгенерированный поиском ответ и сниппет не являются достаточным доказательством обязательного фильтра.

Начальные направления запросов в конфиге: subscription software, recurring transaction marketplace, online business service, developer tools, consumer subscription, workflow automation. Для каждого: компания, клиент, задача, способ регулярной оплаты и рынок. Не отбирать только по известной оценке $300 млн на discovery: масштаб проверяется позже, чтобы были видны причины отсева.

Шаги:
1. Выполнить по одному стартовому запросу на каждое направление; записать запрос, время, результаты и порядок выдачи.
2. Из полученных страниц извлечь до 24 кандидатов с реальными URL. Если не хватает, до 6 дополнительных запросов.
3. Прочитать страницу продукта/цен/описания для каждого кандидата в пределах бюджета. Нечитаемые страницы — discovery issue, не доказательство отсутствия бизнеса.
4. Нормализовать модели. Компания — пример; модель — сочетание покупателя, проблемы, решения и механизма выручки. Два сервиса с одной моделью объединяются и сохраняются как аналоги.
5. Стабильно отсортировать уникальные записи по направлению запроса и порядку появления; брать по очереди из направлений до 12. Сохранять причину объединения/исключения и оставшийся резерв.
6. Зафиксировать batch. После начала фильтров не заменять отклонённых кандидатами из резерва. Новый набор — новый run.

Если неоднозначно, дубликат ли модель, сохранить обе с меткой и приостановить финализацию выборки до проверки владельцем. Нельзя тихо выбирать наиболее перспективные модели до фильтрации.

## Где брать доказательства

| Вопрос | Предпочтительные документы | Ограничение |
|---|---|---|
| Продукт и повторяемая выручка | Официальный продукт, pricing, условия подписки | Маркетинг не доказывает спрос |
| Масштаб компании | Сообщение компании/инвестора о стоимости, биржевая отчётность/данные, публикация с указанным происхождением оценки | Сумма раунда не равна valuation |
| Ограничения деятельности | Официальные регуляторы и документы по релевантной деятельности/юрисдикции | Отсутствие найденного запрета не доказывает законность |
| Клиенты и барьеры | Документы покупателей, публичные условия закупки, кейсы с раскрытым происхождением | Отзывы и кейсы могут быть выборочными |
| Риски | Документация конкурентов, условия, независимые публикации, финансовые сведения | Прогноз отделять от факта |

Дополнительный discovery-каталог: [YC Companies](https://www.ycombinator.com/companies). При проверке 15.11.2026 страница не отдала извлекаемый текст через использованный инструмент; не делать её обязательной зависимостью и не заявлять готовый парсер. Поиск открытого web достаточен для исходного задания.

[Документация Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search) подтверждает возможность поисковых запросов и возврата URL/контента. Конкретные лимиты и стоимость выбранного тарифа проверяются перед интеграцией. Наличие доступного аккаунта не предполагается.

## Контракт чтения

FetchResult: requested_url, final_url, fetched_at UTC, status, title, publisher, published_at nullable, body_text, content_hash, extraction_method, error nullable. Сохранить извлечённый текст внутренне; публично — короткие релевантные фрагменты, ссылки и даты, а не зеркала статей. Даты не выдумывать; неизвестная дата публикации отображается как неизвестная.

Таймаут чтения 20 секунд, максимум 5 редиректов и 5 МБ документа. HTML и текстовые PDF поддерживаются; OCR/логины/paywall не входят в v1. Невозможность прочитать документ не заменяется «знаниями модели». Не обходить ограничения доступа. Ограничения robots/сайта учитываются адаптером; запрещённые страницы остаются inaccessible.

Защита чтения: только HTTP(S), запрет localhost/private/link-local/metadata адресов, проверка DNS и каждого редиректа, запрет URL с credentials. Извлечённый HTML не исполняется. Внешний текст — недоверенные данные, не инструкции агенту.

## Свежесть и повтор

В новом run документы читаются заново; внутри run одинаковый URL можно брать из неизменяемого snapshot. Discovery re-run на сохранённой выборке создаёт новый run, сохраняя candidate IDs и обновляя доказательства. Offline replay использует только snapshots и помечается как replay, не как свежий web-анализ. Изменившийся web и недетерминированный LLM не обещают идентичный повтор; детерминированно воспроизводится расчёт на сохранённых результатах.

Дата события и дата публикации различаются. Историческая оценка допускается как свидетельство достигнутого масштаба с датой; найденная более поздняя существенная переоценка должна учитываться, а не игнорироваться. Для меняющихся тарифов/условий нужен документ, прочитанный в текущем run; это не гарантирует истинность страницы.
