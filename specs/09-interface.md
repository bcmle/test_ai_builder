# 09. Интерфейс и сценарии

Статус: DRAFT v0.4. Язык русский. Публичный посетитель читает опубликованный результат; владелец управляет расчётами.

## Обзор прогона

Верх страницы: дата анализа, рынок, сценарий ресурсов, revision_id и статус «полный/частичный/демонстрационный replay». Счётчики и группы строго по таблице 03-data: итоговый рейтинг; предварительная оценка; нужна проверка; отклонено; не завершено. Рейтинг по возрастанию score с подписью направления; фильтр не меняет места. Provisional показывается отдельно с диапазоном, unavailable — без числа с конкретным вопросом.

Строка модели: название, покупатель/оплата, score либо причина отсутствия, главный риск с подтверждённой фактической основой, компания-аналог, «Открыть» и checkbox «Сравнить». Показывать «проверено N из M», где M — фактический размер подборки, текущую стадию и статус worker. Фильтры/поиск выполняются сервером над всем снимком до пагинации.

## Карточка и источники

Порядок блоков задан в 07-ranking. Клик раскрывает паспорт по method: факт — snapshot, фрагмент, даты и проверка; расчёт — формула, единицы и входные claims; суждение — допущения/предпосылки и явная метка прогноза, ссылка при наличии; human_required — вопрос и основания неопределённости. created_at/fetched_at/published_at/checked_at подписаны отдельно; ещё не выполненная проверка не получает выдуманную дату. Конфликт показывает обе версии и последствия. Ссылка HTTP(S), недоступность видима, сохранённый фрагмент остаётся.

## Сравнение

До трёх моделей одного run/scenario/revision_id. Синхронные строки: покупатель, выручка, общий балл, пять факторов, сроки первой оплаты, бюджет теста, три риска, ограничения. Дни/деньги берутся из QuantityEstimate, не из разбора текста. Одинаковые единицы; неизвестное — «нет данных». На мобильном — горизонтальная прокрутка с закреплёнными названиями строк либо последовательные карточки. Четвёртую добавить нельзя; разные run/ревизии не смешиваются. Owner preview использует draft revision ID из API, публикация гостю не меняется до publish.

## Действия владельца

- Создать live run после просмотра scenario/config и бюджетного лимита.
- Видеть прогресс/ошибку/стоимость, приостановить новые вызовы, возобновить.
- Открыть очередь ручных проверок, добавить основание и решение; видеть новую ревизию.
- Предпросмотреть и опубликовать ревизию. Новый частичный run не заменяет последнюю опубликованную версию сам.
- Скачать результат и очищенный аудит; опубликованные карточки не содержат owner credentials, секреты или приватные технические payload.

## Состояния интерфейса

Пустой проект: понятное описание, гостю «результаты ещё не опубликованы», владельцу создание прогона. Ноль прошедших: причины и исходные модели, без фиктивного победителя. Provider outage: готовые карточки доступны, причина и resume доступны владельцу. Неизвестный ID: 404. Загрузка не скрывает последний сохранённый результат. Ошибки читаемы, сохраняются после обновления страницы. Статусы различаются текстом, а не только цветом; управление клавиатурой и видимый focus обязательны.

## Пользовательская приёмка

На ширине 1440px три карточки сопоставимы по одинаковым строкам. Пользователь за две минуты сравнения трёх карточек может назвать сильнейшую по текущему рейтингу, объяснить два фактора различия и найти источник одного существенного утверждения. Это ручной usability-сценарий, не обещание, что каждый пользователь справится без проверки.

## Дополнение v0.2: рабочий сайт и референс Kelpie

[Kelpie](https://kelpiemoney.com/#how) осмотрен в браузере 15.11.2026: светлая монохромная композиция, крупные чёрные заголовки, мягкие серые подложки, округлые карточки, чёрные кнопки, много свободного пространства; блок How it works — три пронумерованные колонки. Это визуальный ориентир, не выбранный готовый шаблон. Не копируем логотип, бренд, тексты и графические материалы. Внешний вид закрытого кабинета Kelpie не изучался и не предполагается.

### Структура нашего сайта

- `/`: короткий вводный экран, кнопка «Открыть исследование», последний опубликованный результат и три шага «Находим модели → Проверяем риски и доказательства → Сравниваем перспективы».
- `/studies`: исследования по рынкам; США активен первым, остальные показывают очередь/статус. Показатели покрытия означают выполнение плана, не процент всех бизнесов страны.
- `/runs/{id}`: рабочая страница подборки и её рейтинга, поиск по названию/клиенту, фильтры по отрасли/статусу, сортировка по перспективности; дата, сценарий, состав выборки и стадия исследования.
- `/runs/{id}/models/{id}`: полноценная карточка с критериями, факторами, аргументами критика, результатами проверки, доказательствами и планом теста.
- `/runs/{id}/compare`: сравнение до трёх моделей одного сценария.
- `/methodology`: критерии, веса, ограничения, правила статусов и объяснение работы агентов.
- `/owner`: создание/пауза/повтор run, покрытие рынка, очередь ручных вопросов, публикация. Доступ владельца; CEO как посетитель может просматривать опубликованные карточки и историю анализа без права запускать платные запросы.

Каждая карточка содержит не только внешние ссылки: по каждому существенному утверждению доступны фрагмент доказательства, источник, даты, метод, результат проверки и уверенность с объяснением. Ссылки — часть доказательства, не весь результат.

### Предлагаемые дизайн-токены и компоненты

Фон #FFFFFF, вторичный фон #F5F5F5, основной текст #151515, вторичный текст #606060, границы #E5E5E5; это наши предлагаемые значения, не извлечённые CSS Kelpie. Шрифт — системный sans-serif на первом этапе. Радиусы: карточка 24px, элемент управления 12px, основной CTA pill. Контейнер до 1200px; у сравнительной таблицы допускается более широкая область. Состояния дополнительно выделяются умеренными зелёным/янтарным/красным акцентами с текстом и значком, а не одним цветом. Размеры/контраст и адаптивность проверить при реализации.

Главная может быть просторной как референс; аналитические экраны должны помещать значимые поля и сохранять сопоставимость. Не переносить крупные отступы лендинга на каждую строку таблицы. Поддержка reduced-motion; декоративные анимации не блокируют чтение и не являются обязательными. Визуальный макет — следующий артефакт после согласования структуры, сейчас приложение и макет не созданы.

## Дополнение v0.3: каталог и навигация

Добавить `/catalog`: базовые модели, группы по задаче покупателя и фильтры из 13-catalog; поиск, пагинация, отдельные счётчики компаний/базовых моделей/вариантов. Переключатель «Подборка для CEO / Весь каталог» ведёт к текущему run или опубликованному каталогу без смешивания их оценок.

`/catalog/{base_model_id}` раскрывает варианты по сегментам и компании-примеры. Карточка базовой модели не показывает единый выдуманный score: оценки отображаются у конкретных вариантов с рынком, датой и ссылкой на run. Несколько тегов не дублируют карточку и счётчик результатов. Неисследованные записи помечены «не анализировалась»; они не выглядят отклонёнными.

На экране CEO — 10–15 выбранных базовых моделей, видимый выбранный вариант и все статусы. Рейтинг — отдельный блок только прошедших; отказанные не исчезают из подборки. Доступно объяснение «почему включена»: группа и политика отбора. Группы помогают навигации, но не меняют рейтинг. Сравнение до трёх карточек остаётся внутри одного run и сценария; варианты из разных run не сравниваются как один рейтинг.
