# 10. Сбои, лимиты, безопасность и размещение

Статус: DRAFT v0.2. Числа ниже — начальные настройки на ревью.

## Бюджет выполнения

target_models=12; concurrent_models=2; max_active_runs=1; llm_timeout=120s; run_wall_time=45min; max_provider_requests=180; max_search_requests=120; max_document_fetches=180; max_run_cost_usd=15. Время/деньги — пределы, не гарантированная стоимость или обещание уложиться. 90 дней относятся к запуску бизнеса, не длительности анализа.

Локальные квоты: discovery до 12 поисковых запросов/24 кандидатов; research до 4 запросов/6 новых чтений на модель; critic до 3/5; verifier до 6/10. Они являются максимумами, не квотами, которые необходимо израсходовать; общий лимит может остановить раньше. Существенные конфликты используют оставшийся общий бюджет, не получают неограниченные дополнительные вызовы.

Перед вызовом резервировать верхнюю оценку расхода по тарифной конфигурации, лимиту выходных токенов и измеренному/консервативно оценённому входу. Если верхнюю оценку определить нельзя, live run не стартует до настройки лимитов. Вести actual/estimated/unknown отдельно; API billing может запаздывать, hard cap — локальный предел запуска новых запросов, не гарантия итогового счёта. При достижении лимита — paused с причиной и сохранёнными результатами. Изменение лимита владельцем фиксируется событием и версией; автоматического превышения нет.

## Повторы и восстановление

Временные сетевые ошибки, таймаут, rate limit и 5xx: исходная попытка плюс максимум две дополнительные. Задержка min(30s, 2s×2^(attempt-1)) плюс случайная добавка 0..1s; Retry-After имеет приоритет, если укладывается в оставшийся run deadline. Если нет — paused. Автоповторы SDK отключить либо включить в тот же общий счётчик; вложенное умножение запрещено.

401/403, invalid request и исчерпанная квота/баланс не повторяются автоматически. Общая проблема credentials приостанавливает весь run; локальная ошибка документа не блокирует остальные модели. Невалидный структурированный ответ допускает одну корректирующую попытку внутри общего лимита трёх попыток этапа; затем technical_incomplete. Отказ модели и контекстный лимит — отдельные причины, не пустой successful result.

После трёх последовательных временных ошибок одного провайдера приостановить новые запросы к нему на 60 секунд. Уже завершённые результаты сохранить; после паузы один пробный вызов в рамках бюджета. Веб-интерфейс остаётся доступен. Резервного провайдера в v1 нет.

Каждый завершённый этап фиксируется до запуска следующего. После перезапуска worker expired lease возвращается в очередь. Повторный результат не дублирует карточку. Прерванный запрос может быть оплачен провайдером даже без полученного ответа — показывать неопределённый расход.

## Логи

run/model/stage/attempt IDs, timestamp, config/prompt versions, provider/model, duration, tokens/cost при наличии, категория ошибки, источники, переданные агенту данные, результаты валидации и изменения статусов. Пароли, API keys, cookies, Authorization, приватные сетевые реквизиты не логируются. Публичная проекция показывает нужные для проверки независимости payload без секретов и больших исходных статей; полные snapshots — только владельцу.

## Публичный сайт

Один владелец; пароль хранится в виде стойкого хеша, сессия в HttpOnly/Secure/SameSite cookie. Rate limiting входа; CSRF на мутации; гостевой write всегда запрещён. Текст LLM/источников экранируется, HTML источника не рендерится. Экспорты генерируются из разрешённой схемы, не прямым дампом БД. Произвольные команды, URL endpoints провайдера и файловые пути из входов пользователя/агента не выполняются. Защита fetch описана в 02-sources.

## Aeza и GitHub

Размещение на Aeza — подтверждённое решение пользователя. Предлагается VPS с Linux, 2 vCPU/4 GB RAM и persistent storage от 20 GB как стартовый ориентир, не проверенный тариф/нагрузочный расчёт. Тариф, регион, домен и доступы не выбраны. Страница https://aeza.ru/ при проверке 15.11.2026 вернула redirect loop используемому web-инструменту; никаких конкретных доступных тарифов этим документом не утверждается.

До интеграции проверить доступность выбранных LLM/search API из выбранного региона сервера и допустимость использования аккаунта; не обходить региональные ограничения. Если API недоступен, пересмотреть регион или провайдера через изменение спеки.

Публичный GitHub содержит код, спеки, примеры конфигурации без секретов, небольшие синтетические fixtures и инструкции. Не коммитить .env, рабочую БД, полные web snapshots, private logs, секреты или частные данные. Изучить исходный текст тестового на допустимость публикации; если разрешение на его публикацию неясно, не включать оригинал и переписку CEO в публичный репозиторий, оставить собственную спецификацию/описание задачи.

Docker Compose: reverse proxy + web + worker, persistent volume для DB/snapshots. TLS обязателен. Подключённые к БД процессы запускаются от непривилегированного пользователя. Резервная копия согласованным SQLite backup, не копированием активного db-файла без WAL. Backup перед обновлением/миграцией; проверка восстановления до сдачи. Run history не удаляется автоматически в v1; при нехватке диска новый run блокируется. Миграции/rollback фиксируются в release-инструкции.

## Дополнение v0.2: бюджет исследования рынка

Per-run лимиты сохраняются. MarketStudy дополнительно имеет явный суммарный бюджет и счётчики запросов всех дочерних run/discovery cycles. До задания owner лимита первый live study не запускается; бюджет не выводится из числа стран. Исчерпание означает паузу и незавершённое покрытие, а не сигнал переходить к следующему рынку. Состояние очереди стран сохраняется при перезапуске.
